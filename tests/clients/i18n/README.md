It neither logs in nor restores/logs out a session, reads secure preferences, touches account databases, downloads anything, or controls AVD lifecycle. Run only on the parent-verified factory-owned **API34 emulator-5556**, whose entire appearance preference map is known empty. The runner checks that precondition before mutation, persists the exact original map in target internal files, and ultimately checks exact map restoration (including absence of originally absent keys). It uses actual Preferences, MainActivity, Compose accessibility with `uiAutomation.clearCache()`, and the real Activity-owned WorkspaceViewModel.

Use the existing Android toolchain **offline**; no dependency installation/download. Build with the existing selector, quoted as one Gradle argument:

```powershell
./gradlew.bat --offline "-PimSendInstrumentation=im.platform.client.ui.I18nRestartInstrumentation" :app:assembleDebug :app:assembleDebugAndroidTest
```

Retain target `app/build/outputs/apk/debug/app-debug.apk` and test `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`, their SHA256, the build transcript, exact source HEAD and the actual source inventory/diff hashes. Do not assume a prebuilt Compose test APK selects this runner. Parent must verify APK-to-source build provenance; installed-byte hashes alone do not prove source provenance. Parent owns staged builds, installation, serial verification, and final AVD teardown; do not clear application data, delete databases, or run other preference-writing instrumentation concurrently.

Before installation, record `adb -s emulator-5556 shell getprop sys.boot_completed` = 1, `getprop ro.build.version.sdk` = 34 and the owned AVD identity/port. Install exactly those APKs with `adb -s emulator-5556 install -r <retained-target.apk>` and `adb -s emulator-5556 install -r <retained-restart-test.apk>`. Parent records actual package paths and installed bytes; the runner also checks target and test APK sourceDir hashes. No reinstall/update between phases.

Set the following public bindings once in the parent's PowerShell session. Values must come from the retained build inventory, never invented. Clean candidate is `-e cleanCandidate 1 -e wip 0`; WIP is `-e cleanCandidate 0 -e wip 1`. All five phases must carry identical bindings.

Exact phase sequence (retain Recorder argv, elapsed times and full `am instrument` output per invocation). ADB exit 0 alone is insufficient: each output must have `INSTRUMENTATION_CODE: -1`, expected `phaseResult`, and no failure/cleanup/evidence failure. On failure stop dependent phases and execute restore from the parent's `finally` block.

```powershell
adb -s emulator-5556 shell am instrument @restartArgs -e phase setup $restartRunner
adb -s emulator-5556 shell am force-stop im.platform.client
adb -s emulator-5556 shell pidof im.platform.client # empty; retain exit/output
adb -s emulator-5556 shell am instrument @restartArgs -e phase verify $restartRunner
adb -s emulator-5556 shell am instrument @restartArgs -e phase invalid $restartRunner
adb -s emulator-5556 shell am force-stop im.platform.client
adb -s emulator-5556 shell pidof im.platform.client # empty; retain exit/output
adb -s emulator-5556 shell am instrument @restartArgs -e phase verify-invalid $restartRunner
adb -s emulator-5556 shell am instrument @restartArgs -e phase restore $restartRunner
adb -s emulator-5556 pull /sdcard/Android/data/im.platform.client/files/i18n-restart/$restartRun <new-owned-external-evidence-directory>
```

After the second force-stop, `verify-invalid` requires a PID different from invalid and asserts default `en` in the real provider/VM/UI while the invalid stored value remains raw `EN`. `restore` restores the complete original map and reports `RESTORED` with `cleanupComplete=true`. Successful earlier phases report `PHASE_PASSED_CLEANUP_PENDING`; none is final acceptance. PNG manifests contain actual screenshot hashes, sizes, PID/previous PID, source/APK bindings and locale/appearance, with fixed error stage/type rather than exception prose or UI dumps.

Parent must always issue `restore` in a `finally` path, even when an instrumentation invocation times out, is interrupted, or force-stopped before its own finally can execute. Use the same binding/run and `-e phase restore -e attempt cleanup2` for a recovery retry (attempt pattern `[a-z0-9-]{1,24}`; never overwrite an earlier manifest). Preserve failed outputs and any cleanup failure; a later successful restore does not erase the original failure. If the recovery snapshot is missing/mismatched, do not claim cleanup or restart success. Internal `files/i18n-restart/<run>/state.json` remains as the durable appearance/language-only recovery record; external phase manifests/PNGs remain for parent evidence collection. No database or secure-store content is included.

Aggregate restart evidence requires setup/verify/invalid/verify-invalid phase checks, both recorded parent force-stops with absent PID before relaunch, different target PIDs for the two restart comparisons, and final exact restoration.
