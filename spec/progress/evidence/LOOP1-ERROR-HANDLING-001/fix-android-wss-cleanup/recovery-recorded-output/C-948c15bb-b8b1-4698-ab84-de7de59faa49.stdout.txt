# Canonical WSS v1 contract

`envelope.schema.json` is the machine-verifiable wire authority. Every JSON frame has `protocolVersion`, `type`, `requestId`, and `payload`; unknown fields are rejected. A successful `message.ack` has `status: committed`, `messageId`, `seq`, and `createdAt`. The echoed `requestId` identifies the client logical send within its Conversation. `message.created` carries that same request identity for local convergence. Server-generated events use a unique event `requestId` except `message.created`, which carries the originating send request identity.

TLS and WebSocket upgrade produce an unauthenticated connection. Before successful `auth.bind`, only `auth.bind`, `ping`, and `pong` are legal. The access token appears only in `auth.bind.payload`, never in the URL, logs, errors, or fan-out. The server checks signature, expiry, session ID, client type, and session epoch against authoritative session state before binding. A revoked or replaced session emits `session.revoked` and closes the connection; later sends cannot succeed. The `auth.ack` echoes the bind request identity.

For `message.send`, the sender identity comes solely from the bound session. Core authorizes Conversation membership before persistence. `(senderId, conversationId, requestId)` is the server idempotency identity. A repeated send with that identity and identical content returns the original committed `messageId`, `seq`, and `createdAt`; it creates no second Message, sequence, or logical Outbox event. Reuse of the identity with different content is rejected. The same request ID in another Conversation is independent. Sequence numbers increase within each Conversation, while message IDs are globally unique.

`message.ack` with `status: committed` is legal only after the Message, sequence allocation, and matching Outbox event commit atomically in PostgreSQL. A rollback or unknown commit outcome must not yield a successful ACK. A rejected send has no persisted Message or Outbox event. NATS delivery and local `message.created` fan-out can repeat; clients converge by Conversation and request/message identity, and Sync supplies eventual completeness. GROUP send persists one logical Message and one logical Outbox event regardless of member count. WSS v1's send content is `TEXT`; Plugin content requires its separate versioned contract. `message.created` is routed only to locally active, authorized Conversation members; Gateway does not decide business membership.

`contracts/fixtures/websocket/` holds the deterministic shared Go/Java vectors. Run `python contracts/websocket/verify.py` to regenerate and compare them, validate the wire schema, run state assertions, and exercise negative mutations. `python contracts/websocket/verify.py --write` updates generated fixtures intentionally.
# Canonical PostgreSQL schema

`migrations/0001_initial.up.sql` is the shared schema for Go and Java profiles.
Run the migration before application startup, using a normal PostgreSQL `psql`
client and libpq connection settings (`PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`,
and secure credential handling outside the command line):

```text
python3 contracts/database/migrate.py status
python3 contracts/database/migrate.py up
python3 contracts/database/migrate.py down --allow-data-loss
```

The runner applies each SQL file and its checksum ledger entry in one transaction
under a PostgreSQL advisory transaction lock. Applied SQL is immutable. The down
migration drops all product tables and requires explicit data-loss acknowledgement;
release rollback still requires a backup and compatibility assessment.

`sessions` is one row per `(user_id, client_type)` slot. A replacement login must
rotate `session_id`, increment `session_epoch`, and revoke the old session in one
transaction. The server must validate both session ID and epoch against PostgreSQL.
The database constraints reject duplicate normalized friendship and DIRECT pairs,
request IDs and sequence numbers within a Conversation, and duplicate logical
`message.created` outbox events. Message authorization, sequence allocation,
matching Outbox insertion, friend/direct/membership/sync transaction assembly, and
post-commit ACK remain application transaction obligations. A unique constraint
alone cannot prove those multi-row operations occurred atomically.

With a disposable PostgreSQL database configured through libpq variables, run
`python3 -m unittest discover -s tests/database -v`. The integration test uses
an isolated temporary schema and exercises forward, uniqueness, and rollback.
