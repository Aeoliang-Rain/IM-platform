一、增加独立审查环节

流程必须为：

实现 → 常规独立 Review → 新增独立审查 → 提交 GitHub 进行 CI。

新增审查由一个全新、未参与当前候选实现、Fix 或常规 Review 的 Agent 执行，专门检查：

- 没有当前需求依据的防御性检查、异常捕获和兼容分支。
- 空 catch、catch 后返回空值或默认值、Promise.catch 忽略错误等静默兜底。
- 为避免报错或崩溃，把未知异常转换为成功、正常状态或不准确的错误类别。
- 仅打印日志后继续运行，却没有恢复正确状态的异常处理。
- 重复捕获、无意义的错误包装，以及掩盖根因的处理层。

新增审查 FAIL 时，禁止 push、创建或更新会触发该候选 CI 的 PR。由新的 Fix Agent 修复，再由新的常规 Review Agent 审查；常规 Review PASS 后，再由新的独立 Agent 执行新增审查。重复此循环，直到新增审查 PASS。

每次修复形成新候选 SHA，两项审查都必须覆盖最终候选，不能沿用旧 SHA 的 PASS。新增环节只设在提交 GitHub CI 前，不在每次编辑或每条命令前重复执行。它不能代替现有 Review、CI、受保护集成和主仓库同步。
